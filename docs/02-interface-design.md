# 02 · 桌面与手机界面设计规范

日期：2026-10-15 · 状态：设计建议，不是已实现页面

## 1. 设计结论

推荐“轻手作感 + 专业工具画布”。让拼豆作品提供颜色和趣味，界面负责安静、清楚和可控。

不推荐：满屏粉紫渐变、每个按钮不同颜色、大量圆形糖果按钮、正文像素字体、默认深色、上传前同时显示几十个无用操作。

产品初始只设一个“图片转拼豆”工作台。没有社区/商城入口，不做一屏营销大标题后才出现工具。新用户看到上传和结果示意，老用户可直接恢复草稿。

## 2. 视觉系统

### 2.1 颜色基线

| 用途 | 色值 | 使用规则 |
|---|---|---|
| 页面底色 | #F7F8F5 | 只在工作台外壳使用，轻微暖灰 |
| 面板 | #FFFFFF | 设置、弹窗、卡片 |
| 画布衬底 | #EEF1EF | 中性底，不给预览套滤镜 |
| 主色 | #0F766E | 唯一主要动作、选中状态 |
| 主色浅底 | #E8F3F0 | 选中选项背景，与勾选/描边共同使用 |
| 主要文字 | #24312F | 标题、正文 |
| 次要文字 | #5F6F6B | 标签、帮助信息，不用浅灰承载重要说明 |
| 交互边框 | #7B8B86 | 输入框和未选中交互边界 |
| 装饰分隔线 | #E0E6E2 | 不作为唯一识别控件的边界 |
| 强调点缀 | #D7835B | Logo、少量插画；不承担主要按钮或正文 |
| 错误 | #B42318 | 错误说明、破坏性确认 |
| 警告 | #8A4B08 | 参数未应用、内存/存储提示 |

已按 sRGB 对比度公式计算：主色与白色约 5.47:1，正文与白色 13.50:1，次要文字与白色 5.29:1，交互边框与白色 3.57:1，错误与白色 6.57:1。只验证这些具体配对；浅底、hover、disabled 和覆盖层必须在实现时重新检查。

色卡色块属于用户内容，可能对比度不足：必须配色号文字、边框和选择标记，不能仅靠色块传达信息。

### 2.2 字体与密度

- 系统无衬线字体：中文 PingFang SC / Microsoft YaHei / Noto Sans SC，系统字体优先。
- 正文 14–16 px；手机表单输入文字至少 16 px，避免部分 iOS 自动放大。
- 标题 20–24 px，面板标题 16 px，辅助信息 12–13 px；辅助文字不承担必须理解的唯一说明。
- 行高正文 1.5，数值和色号使用 tabular-nums。
- 不用像素字体做正文；Logo 可有少量格子/豆子装饰。
- 8 px 间距体系：4 / 8 / 12 / 16 / 24 / 32。
- 圆角：输入和按钮 10 px，面板 14–16 px；不把每个容器都做成胶囊。
- 除弹窗/浮层外少用阴影，优先边界与留白。

### 2.3 图片显示

- 转换结果使用 nearest-neighbor / image-rendering: pixelated，网格叠加不改变导出内容。
- 普通原图允许平滑缩放，避免把“原图”和“结果”都处理成同一像素效果。
- 透明区域用低对比棋盘格；白色豆子为白色实心格，二者可区分。
- 原图/结果比较必须使用一致裁剪和缩放，否则用户无法判断差别。
- 默认只显示一个大结果视图；不把画布面积分给两块很小的图。

## 3. 信息架构与页面

只有一个工作台，内部四个状态，不使用营销页 → 上传页 → 生成页 → 独立编辑器的多次跳转。

1. 未上传：上传区 + 小型功能说明 + 可继续的草稿。
2. 已上传：预览 + 裁剪/基础参数 + 生成。
3. 已生成：结果 + 基础微调 + 用量 + 下载。
4. 导出：桌面弹窗 / 手机全屏面板，保留当前工作台状态。

裁剪是临时专注模式，完成后返回原工作台；基础编辑不自动跳转新窗口或占满屏幕。

## 4. 桌面布局

### 4.1 ≥1200 px：工作台主布局

- 顶栏 56 px：Logo/“图片转拼豆”、本机保存状态、帮助、项目菜单。
- 左侧为弹性画布区域；右侧参数面板 320–360 px。
- 右侧面板可内部滚动，底部操作区可见；不让整页滚动带走画布。
- 工具栏在画布上方，画布下方显示宽高、实际颜色和豆数摘要。
- 生成后右侧使用“设置 / 用量”页签，同一时刻不叠加第三个固定侧栏。
- 编辑只保留画笔、擦除、取色、移动、撤销/重做；更多操作放到“更多”。

│ [移动] [画笔] [擦除] [取色] [撤销] [重做]    │ 图片  小缩略图 [更换] │
│                                             │          [裁剪]       │
│                                             │                       │
│                大画布                       │ 尺寸  48 × 48 格      │
│                                             │ [32] [48] [64] [96]   │
│                                             │                       │
│                                             │ 最大颜色数 16         │
│                                             │ 色卡 MARD 221         │
│                                             │ 高级设置 ▾            │
│                                             │                       │

按钮会随状态改变：未生成时右侧只有一个实心“生成图纸”；已生成且参数未改时“下载图纸”为实心，“重新生成”为次按钮；参数修改后“应用并重新生成”为实心，“下载上次结果”降为文字入口并明确版本。

### 4.2 768–1199 px：紧凑布局

- 画布保持优先，设置改为可收起的右侧抽屉，打开宽度约 320 px。
- 顶栏显示“设置”按钮；大触屏和平板不能依赖 hover。
- 横屏矮窗口按可用高度处理，避免仅用宽度判断成桌面大面板。
- 浏览器 200% 缩放后允许切换手机式布局，不强制保留侧栏。

## 5. 手机布局

### 5.1 基础原则

- <768 px 使用移动布局，按 390×844 设计基线，同时覆盖 320 px 宽。
- 电脑能力不删除，但改变组织方式，不把整个设置侧栏堆在图片上面。
- 顶部保留小标题、保存状态与更多菜单，不做大型宣传卡片。
- 核心结果在上方，参数通过底部面板修改。
- 底部固定一条主操作；使用 safe-area-inset-bottom 和动态视口单位，给内容留等高 padding，不能遮住最后一行。
- 画布高度随屏幕调整，建议约 36–46dvh、最低约 220 px；短横屏退化为可滚动布局，不硬锁高度。

只在上传区域显示“选择图片”主按钮，不再在底部复制一个相同按钮。

### 5.3 设置与生成

```text
┌────────────────────────────┐
│ ‹ 图片转拼豆      保存中 ⋯  │
├────────────────────────────┤
│ [原图] [结果：待生成]       │
│                            │
│           预览             │
│                            │
│                  [适应]    │
├────────────────────────────┤
│ 48×48格 · 最多16色         │
│ MARD 221                   │
│ [裁剪图片] [调整参数]      │
│                            │
│ 提示：格数越多，细节更多， │
│ 也需要更多豆子。           │
├────────────────────────────┤
│        [生成图纸]          │
└────────────────────────────┘
```

- 点击“调整参数”打开底部面板，约占屏幕 65–80%，内容可滚动。
- 面板内包含格数、颜色数、色卡和折叠的高级项；底部按钮写“应用设置”，只保存表单参数，不生成。
- 返回工作台后显示新参数摘要，用户点击“生成图纸”执行。
- 生成后改参数，按钮为“应用并重新生成”；若存在人工编辑，遵守备份与确认规则。
- 面板同时提供显式关闭按钮；下滑关闭只是附加方式。
- 点击遮罩可关闭普通面板；不丢弃已提交的表单值。裁剪临时变更用“取消 / 完成裁剪”显式提交。

### 5.4 结果与微调

```text
┌────────────────────────────┐
│ ‹ 图片转拼豆     已保存 ⋯  │
├────────────────────────────┤
│ [原图 | 图纸]   [视图 ▾]   │
│                            │
│         结果画布           │
│                            │
│ [−] 150% [+] [适应]        │
├────────────────────────────┤
│ 48×48格 · 13色 · 1,842颗  │
│ [参数] [微调] [用量]       │
│                            │
│ 当前颜色  A01   364颗      │
├────────────────────────────┤
│        [下载图纸]          │
└────────────────────────────┘
```

- 普通浏览默认移动模式，不会误画。
- 进入微调后工具栏明确选中画笔/擦除/取色/移动，选中的工具有文字、图标和背景。
- 单指画笔只在微调模式内改格子；浏览模式下单指只移动画布。
- 双指缩放/移动只在画布内处理；第二指进入时终止或回滚尚未提交的单指笔划，避免缩放误画。
- 避免整页禁用浏览器缩放；提供 + / − / 适应按钮，不要求必须会双指操作。
- 低缩放下格子不足以准确触控时，不直接上色，提示先放大；编辑区内单格可命中区域建议至少约 20–24 px，并提供坐标选格作为替代。
- 手机取色提供当前格色号与坐标提示，不让手指挡住唯一反馈。
- 不将一个轻点同时解释为“高亮颜色”和“修改颜色”。

## 6. 按钮与组件规范

### 6.1 按钮层级

| 类型 | 样式 | 场景 |
|---|---|---|
| 主按钮 | 青绿实底、白字，桌面44px高/手机48px高 | 当前阶段唯一主要任务 |
| 次按钮 | 白底、明显边框、深色字 | 裁剪、重新生成、取消 |
| 轻按钮 | 透明底、文字+图标 | 对比、适应画布、帮助 |
| 工具按钮 | 图标+可访问名称，选中态有底色/边框 | 画笔、取色、移动 |
| 危险按钮 | 仅确认界面使用红色 | 删除本地草稿、明确放弃工作 |

- 同一操作区域最多一个实心主按钮；不同面板不要出现两个相互竞争的主操作。
- 桌面主要控件命中高度至少44px；手机44–48px，主操作48px；图标可以20px，但点击区不能跟着缩小。
- 相邻点击目标建议留8px间隔。此处44px是产品设计目标，不是把 WCAG AA 的24px最低要求误写为44px。
- 按钮名称必须说明结果：“生成图纸”“完成裁剪”“下载 PNG”，不用“确定”“开始”“立即体验”。
- 图标统一线宽和风格；桌面 tooltip 不能代替可访问名称，手机关键按钮显示文字。
- 加载按钮保留宽度和文字，例如“正在生成…”，避免布局抖动。
- 禁用只用于真实不可操作状态，附近说明原因；未上传时隐藏编辑/导出工具，不铺满灰色按钮。

### 6.2 表单与预设

- 滑块旁必须有数值输入和 +/−，不要求精细拖动才能设置。
- 参数名写“图纸尺寸（格）”“最大颜色数”，避免单写“精度”“颜色”。
- 快捷预设使用分段选项/单选按钮，选中态有勾选或明确描边，不单靠颜色。
- 不把12个颜色数快捷按钮平铺满屏；保留4个常用值 + 自定义。
- 数字输入提供上下限、单位、校验提示，输入过程不跳光标或立即重置为默认值。
- 开关仅用于独立即时的二元设置；“立即执行生成”不能伪装开关。

### 6.3 风格入口的处理

本阶段不放“萌宠风 / 日漫风 / 复古风”等实际无法保证的 AI 风格按钮。

已有差异必须可解释：
- “抖动关闭 / 开启”：对应真实算法开关。
- 后续若有“轮廓清晰 / 渐变细腻”预设，必须标注具体参数变化，并允许用户继续改参数。
- “少颜色 / 平衡 / 更多细节”只能是参数预设，不宣称有客观的辨识度星级；没有评测数据就不显示四星、95%还原等分数。

### 6.4 对话框与通知

- 桌面导出面板宽约680–760px，左侧小预览、右侧格式和选项。
- 手机导出使用全屏面板，避免小弹窗内再套滚动区；PDF分页示意与下载按钮可达。
- 对话框打开后焦点进入，关闭后返回触发按钮；Escape可关闭非关键弹窗。
- 成功提示短暂显示但不抢焦点；错误和保存失败保持到用户处理。
- 用 inline 文本解释错误位置；toast 不承载唯一的重要信息。

## 7. 主按钮状态与提示文案

| 状态 | 主按钮 | 辅助文案 |
|---|---|---|
| 未上传 | 选择图片 | JPG、PNG、WebP；基础转换在本设备完成 |
| 已上传 | 生成图纸 | 48×48格，最多16色，MARD 221 |
| 生成中 | 取消生成 | 正在匹配色卡…；无法测量时不用百分比 |
| 已生成 | 下载图纸 | 实际13色，共1,842颗 |
| 参数变更 | 应用并重新生成 | 当前预览仍是上次结果 |
| 有手工修改 | 备份并重新生成（确认窗） | 重新生成不会保留当前手工改色；将先建立恢复点 |
| 保存失败 | 当前主操作不变 | 本机保存失败，请下载项目文件备份 |
| 格数过大 | 保持修改入口 | 当前设备无法处理该尺寸，建议降低到… |

不显示“完美还原”“零色差”“一定牢固”“预计40分钟”等未验证承诺。

## 8. 可访问性与响应式验收约束

- 普通文字至少4.5:1，大文字至少3:1；可识别交互边界/焦点按相关非文本对比要求检查。
- 全键盘可完成上传、参数、生成、导出；画布提供坐标选格与颜色选择的键盘路径。
- 有可见 focus ring，不用仅靠 hover 的帮助。
- 颜色用量表有文本色号，错误用图标+文案，不单靠红色。
- aria-live 播报生成完成/失败，不播报每一个百分比或每次画笔移动。
- 底部面板有正确 dialog 语义、焦点管理和返回按钮；关闭手势不是唯一方式。
- 尊重 reduced-motion，界面转场120–180ms，画布不做装饰性弹跳动画。
- 页面320px宽和200%浏览器缩放可操作；二维图纸本身允许平移，表单与按钮不横向溢出。
- 刘海安全区、软键盘、地址栏收起和横竖屏切换后，主按钮不遮挡输入；导出中旋转屏幕不丢失任务。

## 9. 需要原型验证的决策

- 48格/16色默认值是否适合真实新手输入。
- 手机预览高度与底部参数面板是否让生成路径清楚。
- “设置 / 用量”页签和“参数 / 微调 / 用量”三入口是否易理解。
- 手机画笔的最低可编辑缩放阈值。
- 青绿轻手作风格是否既亲和又不干扰色彩判断。

这些是验证问题，不是要求用户现在逐项作答；开发原型后按验收文档观察真实操作。
