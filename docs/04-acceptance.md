# 04 · 开发与验收清单

日期：2026-10-15 · 当前状态：仅文档，下面所有实现验收尚未执行。

## 1. 开发顺序

均属于图片转换模块，不启动新业务模块。

### A. 先打通真实转换

- [ ] 响应式工作台、上传、图片校验、方向处理、裁剪。
- [ ] 明确版本的合法来源色卡。
- [ ] 格数/颜色预算/透明处理/色卡映射。
- [ ] Worker任务、取消、错误恢复。
- [ ] 真实结果预览和用量统计，不用静态假结果代替。
- [ ] 先完成PNG和项目文件输出，形成内部测试闭环。

### B. 补齐编辑和正式输出

- [ ] 画笔、擦除、取色、移动、撤销重做。
- [ ] 全局换色、色号高亮、坐标。
- [ ] 待应用参数和有效图纸版本分离。
- [ ] 人工编辑的重新生成确认和恢复点。
- [ ] PDF分页、CSV、导出预览、文件大小保护。
- [ ] IndexedDB草稿、恢复、配额失败处理。

### C. 打磨后再开放新模块

- [ ] 桌面鼠标/键盘和手机触控完整闭环。
- [ ] 算法盲评和代表图实际拼制。
- [ ] Safari、Android、微信内浏览器的兼容和降级。
- [ ] 性能、内存、无障碍、异常和隐私检查。
- [ ] 基于用户测试修正默认参数、提示文案和操作入口。

## 2. 页面与交互验收

- [ ] 未上传首屏有明确的唯一“选择图片”入口，无大量灰色工具。
- [ ] 390×844上传后能看到有意义的预览和主操作，不需滚过整张参数表。
- [ ] 手机设置从预览打开，关闭后保留参数，能明确回到生成。
- [ ] 生成完成后主操作变成“下载图纸”，不与同权重按钮竞争。
- [ ] 参数变更显示未应用提示，旧预览不会被标为新参数结果。
- [ ] 上传新图或重新生成不会无提示丢失已编辑作品。
- [ ] 普通浏览不误画；微调工具选中状态明确。
- [ ] 单指/双指切换不产生意外笔划；画布外页面仍能滚动和缩放。
- [ ] 软键盘弹出时字段和面板提交按钮可达。
- [ ] 弹窗返回、系统后退、Escape不丢失未提交编辑，也不困住焦点。
- [ ] 原图与结果的裁剪/方向一致，可以有效比较。

## 3. 算法与数据一致性

- [ ] 所有非空格子都属于作品记录的色卡版本。
- [ ] 实际颜色种类不超过用户设置的最大颜色数。
- [ ] 总豆数 = 非空格数 = 各颜色数量之和。
- [ ] 编辑、替换、撤销/重做后上述等式仍成立。
- [ ] 同一图片、算法版本、参数生成可重复结果；使用随机算法时固定并记录种子。
- [ ] 空格与白色豆子分离，透明边缘不出现无解释黑边。
- [ ] 裁剪和EXIF方向测试通过。
- [ ] Worker旧结果不能覆盖更新请求，取消后不回写草稿。
- [ ] 导入项目验证矩阵长度、索引和版本；不信任导入统计。
- [ ] 切换色卡需要重新生成/明确重映射，不能只改品牌标签。

## 4. 固定测试集与算法评测

至少准备有授权的30张图片：照片人像5、宠物5、平涂插画5、像素原图5、文字/细线5、透明/渐变5。另加损坏文件、全透明、纯色、细长图、超大图作为边界测试。

统一比较32/48/64格长边、8/16/24色，抖动开/关。参与比较的图片、裁剪、色卡和颜色预算必须相同。

记录：
- 原图主体可辨识度、关键轮廓与小特征是否保留。
- 实际颜色数、孤立格数量、各色用量。
- 区域色差等辅助指标；不能只按单一像素误差选择方案。
- 抖动是否制造过多难拼碎点，去杂点是否误删眼睛/高光。
- 至少5位新手完成上传→生成→修正→导出任务，目标至少4人无需研究员代操作即可完成；这是小样本发现问题的门槛，不是统计显著性或商业需求证明。
- 至少选3张代表图实际备料和拼制，验证色号/统计/图纸可读性；记录实物色差和操作问题，不承诺绝对色准。

## 5. 导出验收

- [ ] PNG尺寸、图例、色号与导出设置一致，不截字、不模糊。
- [ ] 透明/空格不误计数量；镜像导出明确标记，不暗中改变编辑矩阵。
- [ ] PDF字体嵌入/中文显示可用，多页编号、坐标和拼接关系一致。
- [ ] 施工图按可读格尺寸分页，避免128格挤在一页导致色号无法阅读。
- [ ] 如提供1:1打印，校准尺和“实际大小打印”说明可见，实测比例通过。
- [ ] CSV中文、逗号、换行与公式注入防护通过。
- [ ] 项目导出→重新导入后，格子、色卡、参数和统计保持一致。
- [ ] 手机内存不足有可恢复提示，推荐分页而非崩溃/空白下载。
- [ ] iOS Safari、Android Chrome验证文件实际可打开；微信不支持时提供明确外部浏览器或长按保存降级。

## 6. 建议性能预算

以下是拟定目标，不是已实现成绩。测试必须记录设备、操作系统、浏览器、图片尺寸、参数和算法版本。

| 场景 | 初始目标 |
|---|---|
| 一般点击和编辑反馈 | 视觉反馈尽量小于100ms；重计算不占主线程长任务 |
| 12MP图片选入至可裁剪预览 | 代表性中端手机尽量在3秒内 |
| 常规64格长边/16色转换 | 代表性中端手机尽量在3秒内 |
| 最大128×128/32色转换 | 尽量在10秒内；超1秒给阶段提示，支持取消 |
| 本地草稿保存 | 编辑后约1秒防抖，失败可见，操作不阻塞 |

若CIEDE2000或低端设备达不到目标，先做缓存、减少候选色、预计算或近似算法对比，不得为了显示快而悄悄改变用户要求的输出。

## 7. 跨端测试矩阵

布局视口：320×568、360×800、390×844、430×932、768×1024、1024×768、1280×720、1440×900；另测短横屏及200%浏览器缩放。

真实设备/浏览器至少覆盖：
- Windows Chrome、Edge；macOS Safari和Chrome。
- iPhone Safari，至少一个较小屏幕；Android Chrome，至少一台中低端设备。
- 微信内置浏览器作“支持或可降级”验证，不能仅改UA声称通过。
- 手机横竖屏、地址栏收起、软键盘、后台恢复、浏览器存储清理。

逐个记录支持等级：完整支持 / 降级支持 / 不支持并明确提示。没有测试的环境标“未验证”。

## 8. 异常与隐私

- [ ] 不支持/损坏/超限图片有具体提示，原草稿保留。
- [ ] 取消转换、重复点击、连续改参数、新图解码中退出不会串结果。
- [ ] IndexedDB禁用、配额满、写入失败不会假显示“已保存”。
- [ ] 失败时提供项目文件下载备份。
- [ ] 基础转换网络检查中没有图片上传；第三方统计不采集图片、色号矩阵、作品名或私人文件名。
- [ ] 未生成云端能力前不索取照片上传授权；将来启用云处理必须单独告知。
- [ ] 清除本机数据只清本应用作品，需确认，不误删其他站点数据。
- [ ] 导入JSON不触发脚本、危险URL或无限资源申请。

## 9. 完成此模块的发布门槛

1. 主路径、版本保护、统计和导出一致性全部通过，无数据丢失类问题。
2. 桌面和手机各能独立完成完整流程。
3. 性能预算有真实测试结果，未达标项有明确降级和提示。
4. 测试集结果、至少3份实际拼制记录及新手测试问题有留档。
5. 导出、草稿恢复、隐私、无障碍的关键项通过。
6. 阻断/严重问题关闭后，再决定是否进入图库等新模块。
